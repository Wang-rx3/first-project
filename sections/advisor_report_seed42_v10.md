# 3 UAV Local EKF GAT MAPPO 阶段性实验进展汇报

**实验阶段：** seed=42 单种子开发实验 
**实验对象：** 3 架 UAV、Moderate 场景、GNSS denied、50 步 episode 



## 一 当前已经实现的内容

| 模块 | 当前实现情况 |
|---|---|
| 本地协同定位 | 每架 UAV 使用本地 EKF，融合 IMU、视觉里程计和协同 UWB 信息 |
| 动态通信拓扑 | 根据链路质量、邻居消息和通信状态构造局部图，并由 GAT 编码 |
| MAPPO 决策 | 使用集中训练、分散执行方式，联合决定测量选择、带宽和运动动作 |
| 通信建模 | 记录测量次数、512 字节等效负载、丢包率、时延、AoI 和通信代价 |
| 实验隔离 | train 用于训练，validation 用于性能判断，test 只生成和封存 |
| 对比方法 | Local-only、Random、Greedy 和 Proposed 四种方法均完成 validation 对比 |

| 基线                 | 具体含义                                                     | 作用                                             |
| -------------------- | ------------------------------------------------------------ | ------------------------------------------------ |
| `local_only_fixed`   | 每架 UAV 只使用本地 EKF，不使用邻居协同测量；采用固定运动和通信控制 | 弱基线，去掉邻居协同测量，检验协同定位是否有价值 |
| `random_cooperative` | 在合法邻居中随机选择测量源，执行协同 UWB 更新                | 随机基线，检验随机协同是否已经足够有效           |
| `budgeted_greedy_ig` | 在通信预算内，选择当前预测信息增益最大的邻居                 | 强规则基线，检验 MAPPO 是否能超过即时贪心选择    |

## 二 五张主图分析

### 图 1 累计团队回报

![图1 每回合累计团队回报](../plots/preliminary/advisor_report_seed42_v10/01_episode_return.png)

图 1 的横轴是训练 episode，纵轴是**单个 episode 内窗口奖励的累计值**，不是跨 episode 的运行总和。图中红色 `X` 是碰撞导致的终止；本次 100 个训练回合中共有 13 个碰撞终止。达到 50 步的正常回合不显示异常标记。

曲线大约在 `-16` 到 `-33` 之间大幅波动，没有明显的“越来越不负”的趋势。深谷通常与**碰撞**、较大的即时惩罚或不同场景难度有关。累计回报还会受到回合长度影响：回合越长，负奖励累加次数越多，所以累计值不能单独用来判断策略优劣。当前训练并没有真正改善奖励

训练过程能够正常运行，但当前没有足够证据说明策略已经稳定学会更优策略。

### 图 2 平均团队奖励

![图2 每窗口平均团队奖励](../plots/preliminary/advisor_report_seed42_v10/02_mean_team_reward.png)

图 2 使用每个 episode 的平均窗口奖励，减弱了回合长度对累计奖励的影响。大多数回合位于 `-0.3` 到 `-0.5` 附近，但仍出现约 `-0.8` 到 `-1.1` 的深跌。

这说明奖励波动不只是累计方式造成的。主要影响包括：训练阶段仍在探索、场景和通信状态具有随机性、部分回合发生碰撞、碰撞惩罚相对稀疏但幅度较大。平均奖励同样没有稳定上升，因此目前只能说策略在学习过程中保持有限数值范围，不能说已经收敛。

### 图 3 MAPPO 损失

![图3 MAPPO损失及其分量](../plots/preliminary/advisor_report_seed42_v10/03_training_loss.png)

图 3 包含 total loss、actor loss 和 critic loss。由于采用四个 episode 收集一次 PPO 更新，100 个训练回合大约对应 25 个 update，因此横轴点数较少。

- total loss 和 critic loss 总体从较高水平下降到较低水平，说明价值函数拟合并未持续发散；
- total loss 的变化与 critic loss 较为接近，说明当前总损失主要受 critic 目标误差影响；
- actor loss 大多在零附近波动，但中后期出现明显尖峰，说明策略梯度仍具有较高方差；
- loss 有限并不等于定位性能已经改善，loss 只能说明训练数值链路是否稳定。

### 图 4 定位误差对比

<img src="D:\research project\sections\advisor_report_seed42_v10.assets\image-20260907122834301.png" alt="image-20260907122834301" style="zoom:50%;" />

图 4 使用 validation 数据，对四种方法比较位置向量范数 RMSE 。20 个 validation episode 的汇总如下：

| 方法 | RMSE（m） | 解释 |
|---|---:|---|
| Local-only | 0.438 | 不进行协同测量，作为弱参照 |
| Random | 0.418 | 随机选择邻居，定位有所改善 |
| Greedy IG | 0.401 | 当前最强的即时信息增益规则 |
| Proposed | 0.410 | 明显优于 Local，略优于 Random，但略差于 Greedy |

**得到的信息：** Local-EKF-GAT-MAPPO 确实利用**协同信息取得了定位收益**，不能说方法完全没有作用。但 Greedy 在当前场景下的即时测量选择更有效，说明 MAPPO 尚未稳定学会 Greedy 所利用的局部信息增益关系。Proposed 的点分布仍较宽，说明方法对场景变化越敏感，稳定性较差。

### 图 5 通信性能对比

![图5 通信性能对比](../plots/preliminary/advisor_report_seed42_v10/05_communication_performance.png)

图 5 显示测量负载、候选通信代价和丢包指标。Proposed 的实际测量负载约为 `33.6 kB/episode`，Random 和 Greedy 分别约为 `32.4 kB/episode`，Local-only 为零是其不执行协同测量的定义结果。

这暴露出当前主线最关键的通信问题：Proposed 能改善 RMSE，但没有用更少的测量达到该精度，反而比两个规则协同方法产生更多负载。Proposed 的 `J_com` 约为 `0.037`，低于 Random 和 Greedy 的约 `0.058`，这并不矛盾，因为 `J_com` 还包含丢包、时延、AoI 和连通性等综合因素，不能替代实际字节负载。论文中必须同时报告这两个指标。

## 四 当前暴露出的主要问题

### 1 训练奖励没有形成清晰的改善趋势

表现为累计奖励和平均奖励都存在深跌，后期没有稳定地变得不那么负。原因主要是训练奖励同时受到碰撞、通信状态、定位不确定度和随机场景影响；碰撞发生时，单个 episode 的回报目标会突然改变，critic 需要拟合的目标方差增大。

### 2 定位和通信目标还没有同时达到较好水平

Proposed 比 Local 定位更好，但比 Greedy 的 RMSE 略差，且测量负载更高。也就是说，当前方法形成了“定位收益—通信开销”的权衡，但通信效率还没有体现出 GAT 和 MAPPO 的明显优势。



因此，下一阶段的重点不是继续美化奖励曲线，而是验证“测量动作是否真的产生可学习的定位收益”，并进一步对齐实际通信负载。完成这两项后，再进行多随机种子确认实验。
